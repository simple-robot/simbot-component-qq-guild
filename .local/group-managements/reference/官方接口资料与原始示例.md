# 官方接口资料与原始示例

## 使用说明

本页是在 2026-09-10 从 `docs.md` 的 17 个 QQ 官方 v2 页面逐页读取后整理的离线契约。字段名、路径、频率和示例均保留官方写法；表格为便于实施的等义转录。实现时以 JSON 字段名为准，Kotlin 名称统一改为 camelCase 并标 `@SerialName`。

“请求体”出现在若干 GET 页面中是官方页面标题的写法；它们的 `cursor`、`limit` 必须作为 URL query 参数。HTTP 示例、接口频率和内邀/权限提示不得自行扩写。

## A. 群资料与机器人状态

### 1. 获取群基本信息

来源：[官方页](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_info.get.html)（官方更新 2026-08-10）。

| 项目 | 值 |
| --- | --- |
| HTTP | `GET /v2/groups/{group_openid}/info` |
| 频率 | 30 QPM |
| 路径参数 | `group_openid: string`，必填，群 OpenID |
| 响应 | `group_openid: string`、`group_name: string`、`group_finger_memo: string`、`group_class_text: string`、`group_tags: []string`、`group_member_num: integer` |
| 错误码 | `11253`：应用无接口访问权限；官方建议联系平台申请白名单。 |

官方请求示例：

```http
GET /v2/groups/3E5D8A1F7B2C9E4D6A0F1B3C5D7E9F2A/info
```

官方响应示例：

```json
{
  "group_openid": "3E5D8A1F7B2C9E4D6A0F1B3C5D7E9F2A",
  "group_name": "读书分享会",
  "group_finger_memo": "每周共读一本好书",
  "group_class_text": "文化",
  "group_tags": ["阅读", "文学", "成长"],
  "group_member_num": 256
}
```

### 2. 获取机器人群内状态

来源：[官方页](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_bot_state.get.html)（官方更新 2026-08-10）。

| 项目 | 值 |
| --- | --- |
| HTTP | `GET /v2/groups/{group_openid}/bot_state` |
| 频率 | 30 QPM |
| 路径参数 | `group_openid: string`，必填 |
| 响应 | `member_openid: string`；`joined_at: string`（RFC3339）；`allow_proactive_msg: boolean`；`recv_msg_setting: string`（`all`、`only_mention`、`mention_and_context`）；`member_role: string`（`member`、`owner`、`admin`） |
| 错误码 | `11253` 白名单限制。 |

官方请求示例：

```http
GET /v2/groups/3E5D8A1F7B2C9E4D6A0F1B3C5D7E9F2A/bot_state
```

官方页面的响应示例末行原文缺少结束引号，**不能**直接作为 JSON 测试夹具；测试应在保留其字段语义的前提下补成合法 JSON：

```text
{
  "member_openid": "7A3B9C1D5E2F4A6B8C0D1E3F5A7B9C2D",
  "joined_at": "2025-06-15T14:30:00+08:00",
  "allow_proactive_msg": false,
  "recv_msg_setting": "only_mention",
  "member_role": "member
}
```

### 6. 设置群成员禁言

来源：[官方页](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_restrict_chat_setting.post.html)（官方更新 2026-09-03）。机器人需为群管理员，最大禁言时长 30 天。

| 项目 | 值 |
| --- | --- |
| HTTP | `POST /v2/groups/{group_openid}/restrict_chat_setting` |
| 频率 | 60 QPM |
| Body | `members: []SetMemberMuteState` 可选，单次最多 20 个 |
| 单项 | `op` 必填：`add`/`update`/`del`；`member_openid` 必填。增加/更新只能作用普通成员，不能作用群主、管理员、机器人；`mute_expire_at` 可选，RFC3339，`del` 时空串代表立即解除。 |
| 响应 | 无，官方示例 `{}` |

官方示例：

```http
POST /v2/groups/30584554AA2BF4E72BD3B8F27A70339D/restrict_chat_setting

{
  "members": [{
    "op": "add",
    "member_openid": "EC58D87F598C8294A533B9D458DAAF33",
    "mute_expire_at": "2026-08-05T11:23:05+08:00"
```

### 8. 创建策略

来源：[官方页](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_join_approval_strategy.post.html)（官方更新 2026-08-10）。每个机器人最多 20 个策略；关联群中机器人是管理员时规则才会生效。

| 项目 | 值 |
| --- | --- |
| HTTP | `POST /v2/groups/join_approval_strategy` |
| 频率 | 60 QPM |
| Body | `group_openids` 与 `group_ids` 二选一必填，二者都传或都不传会错；各最多 100。`group_ids` 是 uint64 群号列表。`is_enable` 可选 `on/off`、默认 `on`；`expire_at` 可选 RFC3339、默认一年；`remark` 可选、最多 255 汉字。 |
| 回执 | `strategy_id`、`is_enable`、`expire_at` |

官方请求示例（占位符文本按官方原样表达，不能作为真实 OpenID）：

```http
POST /v2/groups/join_approval_strategy

{"group_openids":["<xxxxxxxx1","xxxxx2>"],"is_enable":"on","expire_at":""}
```

官方响应示例：

```json
{
  "strategy_id": "st_d83eca11e9",
  "is_enable": "on",
  "expire_at": "2027-08-05T15:30:16+08:00"
}
```

| 项目 | 值 |
| --- | --- |
| HTTP | `PATCH /v2/groups/join_approval_strategy/{strategy_id}` |

官方示例：


```json
{"is_enable":"off","expire_at":"2027-08-05T15:30:16+08:00"}
```

### 17. 群黑名单操作

来源：[官方页](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_member_blacklist.post.html)（官方更新 2026-09-03）。只有目标用户不在群内时才能加入黑名单。

| 项目 | 值 |
| --- | --- |
| HTTP / 频率 | `POST /v2/groups/{group_openid}/member_blacklist`；60 QPM |
| Body | `op: string` 必填，`add`/`del`；`member_openids: []string` 必填，单次最多 20。 |
| 回执 | `fail_openids: []string`；官方说明 add 时为拉黑失败 OpenID，del 时同义。 |
| 错误码 | `11253` 白名单限制。 |

官方添加示例：

```http
POST /v2/groups/3E5D8A1F7B2C9E4D6A0F1B3C5D7E9F2A/member_blacklist

{"op":"add","member_openids":["7A3B9C1D5E2F4A6B8C0D1E3F5A7B9C2D"]}
```

官方移出示例：

```http
POST /v2/groups/3E5D8A1F7B2C9E4D6A0F1B3C5D7E9F2A/member_blacklist

{"op":"del","member_openids":["7A3B9C1D5E2F4A6B8C0D1E3F5A7B9C2D"]}
```

```json
{"fail_openids":[]}
```

## 实施时必须保留的官方限制

1. `group_openids` 与 `group_ids` 在创建策略时是严格二选一；修改关联群也必须沿用创建时的标识形式。
2. `execute` 是约十分钟的异步扫描，无状态查询接口；任何“等待完成”功能都是虚构能力。
3. 成员禁言的 `del` 用空 `mute_expire_at` 表示立即解除；SDK 不应把它改成当前时间。
4. 独立黑名单的 add 前提是成员已离群；不要在 SDK 内偷偷执行两个网络请求来改变这个前提。
5. 成员列表没有官方 `limit` 参数；只传 `cursor`。不要把其他列表的 `limit` 误复用过去。
