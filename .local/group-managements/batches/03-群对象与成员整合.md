# 批次 3：群对象与成员整合

## 目标

批次 1、2 提供的是原始 HTTP SDK；本批让适合 simbot 群语义的能力真正落到现有 `QGGroup`、`QGGroupMember` 和群管理事件所返回的对象上。重点是替换过去“官方没有能力”留下的空实现，而不把网络 I/O、全局策略或本地状态机塞进错误的抽象。

依赖：批次 1、2 的 API 已通过请求构造测试。实现不等待内邀资格；平台返回 `11253`、权限或内邀错误时继续抛出原始 `QQGuildApiException`。

## 1. 保持与改变的边界

| 现有行为 | 本批后行为 | 原因 |
| --- | --- | --- |
| `QGGroup.name` 固定空串 | **保持不变**。 | `name` 不是挂起属性；属性读取时查询远端会隐藏 I/O、阻塞和失败。 |
| `QGGroup.members` 空 `Collectable` | 返回冷、自动翻页的成员 `Collectable`。 | 官方现已提供成员列表；它和 `QGGuild.members` 的语义可直接对齐。 |
| `QGGroup.member(id)` 恒为 `null` | 查询成员详情；平台 404 映射为 `null`，其他错误继续抛出。 | 与 `QGGuildImpl.queryMember` 的现有约定一致。 |
| `QGGroup.ownerId` 恒为 `null` | **保持不变**。 | 没有“获取群主”单独资源；成员列表未必完整、仍为内邀，不能从中猜测 owner。 |
| 机器人/成员事件中的 `QGGroupMember` 仅有 OpenID | 仍可只含 OpenID，但新增可空的补充字段；由列表/详情得到的实现填充它们。 | 事件载荷不包含完整资料，不能伪造。 |
| `GroupRelation.group(id)` 产生未校验的包装对象 | **保持不变**。对象新增 `info()` 等显式查询，失败由平台返回。 | 不隐式请求，也不破坏当前“伪 group”契约。 |
| 入群自动审批策略 | 不放进 `QGGroup`。 | 一个策略关联多群且资源路径无群 OpenID；批次 4 放入 `QGBot`。 |

## 2. `QGGroup` 的公共表面

在 `simbot-component-qq-guild-core/.../group/QGGroup.kt` 增加下列成员。每个成员以多行 KDoc 说明是否请求网络、管理员/内邀前置条件、返回快照是否缓存以及可抛出的 `QQGuildApiException`。

```kotlin
/** 查询群资料的瞬时快照；每次调用均请求 QQ API。 */
@ST
public suspend fun info(): QGGroupInfo

/** 查询机器人在此群的状态；每次调用均请求 QQ API。 */
@ST
public suspend fun botState(): QGGroupBotState

/** 群成员的冷分页集合；开始收集时才请求，直到 next_cursor 为空。 */
override val members: Collectable<QGGroupMember>

/** 按 OpenID 查询成员；平台未找到时返回 null。 */
@ST(... existing getMember transform names ...)
override suspend fun member(id: ID): QGGroupMember?

/** 拉取入群申请；autoPagination=false 时只取得一页。 */
public fun joinRequests(
    startCursor: String? = null,
    limit: Int? = null,
    autoPagination: Boolean = true,
): Collectable<QGGroupJoinRequest>

/** 查询群全员/成员禁言状态的瞬时快照。 */
@ST
public suspend fun restrictChatState(): QGGroupRestrictChatState

/** 按官方 add/update/del 更新成员禁言；单次上限和成员角色限制由平台裁决。 */
@ST
public suspend fun updateMemberMutes(updates: List<GroupMemberMuteUpdate>)

/** 批量移除成员，可明确选择平台的“移除后同时拉黑”。 */
@ST
public suspend fun removeMembers(
    memberIds: Collection<ID>,
    addToMemberBlacklist: Boolean = false,
): QGGroupMemberRemovalResult

/** 拉取群黑名单；autoPagination=false 时只取得一页。 */
public fun blacklistedMembers(
    startCursor: String? = null,
    limit: Int? = null,
    autoPagination: Boolean = true,
): Collectable<QGGroupBlacklistUser>

/** 显式批量加入黑名单；目标必须已不在群内。 */
@ST
public suspend fun addMembersToBlacklist(memberIds: Collection<ID>): List<ID>

/** 显式批量移出黑名单；返回平台报告的失败 OpenID。 */
@ST
public suspend fun removeMembersFromBlacklist(memberIds: Collection<ID>): List<ID>
```

`members` 的 getter 等价于一次完整自动分页，而不是已有空集合。成员列表官方没有 `limit`，因此不设计假的 `members(batch: Int)` 重载；需要单页或指定 cursor 的调用者用低层 `GetGroupMemberListApi`。`joinRequests/blacklistedMembers` 则按现有 `QGCommandPanelManager.list` 提供 `autoPagination`，因为官方确实给出 limit/cursor。

`updateMemberMutes` 仅把 `updates` 放进 `GroupMemberMuteUpdateRequest`；不主动把 `del` 改为 `muteExpireAt=""`。若需要这种语义，调用者显式构造 `GroupMemberMuteUpdate(op = OP_DEL, memberOpenid = ..., muteExpireAt = "")`。

## 3. 新增 core 快照和成员模型

在同一 `group` 公共包新增 `QGGroupManagementSnapshots.kt`（或按职责拆分文件）。所有快照实现 `QGObjectiveContainer<低层模型>`，从而与 `QGGuild`、自定义菜单和指令面板一致。

| core 类型 | `source` | 对外投影 |
| --- | --- | --- |
| `QGGroupInfo` | `GroupInfo` | `id`、`name`、`fingerMemo`、`classText`、`tags`、`memberCount`。这是查询资料的结果，不替换 `QGGroup.name`。 |
| `QGGroupBotState` | `GroupBotState` | `memberId`、`joinedAt`、`allowProactiveMessage`、`receiveMessageSettingValue`、`memberRoleValue`；已知角色映射 `memberRole: QGGroupRole?`。 |
| `QGGroupRestrictChatState` | `GroupRestrictChatState` | `globalRule` 与 `mutedMembers`，原始 RFC3339 字符串可经明确的实验性便利属性转 `Timestamp`。 |
| `QGGroupJoinRequest` | `GroupJoinRequest` | 申请字段、`group: QGGroup`，以及 `approve()`、`decline(reason, addToBlacklist)`。 |
| `QGGroupBlacklistUser` | `GroupBlacklistUser` | `id`、`name`、`isBot`、`unionOpenid`、`bannedAt`。它不是 `QGGroupMember`，因为用户已不在群内。 |
| `QGGroupMemberRemovalResult` | `GroupMemberRemovalResult` | `removeResultValue`、`removed`（仅 `success` 时 true）与 `blacklistFailureIds`；保留 source 供调用方处理部分失败。 |
| `QGGroupMemberInfo` | `GroupMember` | `QGGroupMember` 的富实现；由成员列表/详情返回。 |

`QGGroupJoinRequest.approve()` 必须创建 `GroupJoinRequestApproval(OP_APPROVE, joinRequestId = source.joinRequestId.ifEmpty { null })`。`decline` 同理但显式传 `OP_DECLINE`、`rejectReason` 和 `addToMemberBlacklist`。它们不自动把 `riskTips` 解释成拒绝依据、不记录问答答案、不执行额外黑名单请求。

### 3.1 扩展 `QGGroupMember`，但不臆造事件资料

在现有 `QGGroupMember.kt` 为基础接口新增带默认 getter 的公开属性：

```kotlin
/** 平台原始群角色；事件未携带或未知时为 null。 */
public val memberRoleValue: String? get() = null

/** 映射后的 OWNER/ADMIN/MEMBER；未知原始角色时为 null。 */
public val memberRole: QGGroupRole? get() = null

/** 平台是否标记为机器人；事件未携带时为 null。 */
public val isBot: Boolean? get() = null

/** 加群 RFC3339 时间；事件未携带时为 null。 */
public val joinedAt: String? get() = null

/** 开放平台统一标识；平台未提供时为 null。 */
public val unionOpenid: String? get() = null
```

`QGGroupMemberInfo` 覆盖这些属性，并将 `name` 覆盖为 `source.username`；`nick`、`avatar` 仍遵循 QQ 群 API 未提供而返回 `null`。`QGGroupAuthor` 的已有非空 `memberRole: QGGroupRole` 和 `isBot: Boolean` 是可空基类属性的合法协变覆盖；实现补充 `memberRoleValue` 的已知原始值，保持消息事件对象也能提供一致角色文本。

`QGGroupMemberImpl` 与 `QGBotMemberImpl` 不得填充“普通成员”“非机器人”等猜测值，继续使用默认 null。这样群管理事件与消息事件保持其实际载荷边界。

## 4. 内部委派与分页算法

### 4.1 放在 `QGBotImpl` 的查询辅助函数

仿照已有 `queryGuild`、`queryMember`、`queryGuildRoles`，新增内部函数而非让每个 `QGGroupImpl` 复制 `requestDataBy(source)`：

```text
queryGroupInfo(groupOpenid): GroupInfo
queryGroupBotState(groupOpenid): GroupBotState
queryGroupMember(groupOpenid, memberOpenid): GroupMember?
queryGroupMembers(groupOpenid): Flow<GroupMember>
queryGroupJoinRequests(groupOpenid, startCursor, limit, autoPagination): Flow<GroupJoinRequest>
queryGroupRestrictChatState(groupOpenid): GroupRestrictChatState
updateGroupMemberMutes(groupOpenid, updates): Unit
removeGroupMembers(groupOpenid, ids, addToBlacklist): GroupMemberRemovalResult
queryGroupBlacklist(groupOpenid, startCursor, limit, autoPagination): Flow<GroupBlacklistUser>
modifyGroupBlacklist(groupOpenid, op, ids): GroupMemberBlacklistOperationResult
```

`queryGroupMember` 仅捕获已存在的 `QQGuildApiException.ifNotFoundThenNull()` 分支；非 404（11253、401、403、限频、序列化问题）原样上抛。其他查询不把任何 HTTP 错误转换为空流。

### 4.2 正确的冷分页

所有 Flow 在 builder 内部才初始化 cursor、发送请求和 emit，随后再 `asCollectable()`；不能在 getter 或函数调用时预取第一页。基本算法如下：

```kotlin
flow {
    var cursor = startCursor
    do {
        val page = bot.executeData(GetGroupJoinRequestListApi.create(groupOpenid, cursor, limit))
        page.list.forEach { emit(it.toSnapshot(group)) }
        if (!autoPagination || page.nextCursor.isEmpty()) break
        cursor = page.nextCursor
    } while (true)
}.asCollectable()
```

成员列表唯一差异是结果字段 `members` 且请求不传 limit。黑名单使用 `users`。保持 `QGCommandPanelManagerImpl` 的行为：不设缓存、不设猜测性的最大页数、不悄悄去重；如果服务端循环返回相同 cursor，调用方会观察到问题，而不是 SDK 丢数据。

### 4.3 `QGGroupImpl` 只做资源定位

在 `internal/group/QGGroupImpl.kt` 的 overrides 只把 `id.literal` 传给 `QGBotImpl` 辅助函数，再将低层数据映射为快照。发送消息相关 `sourceEvent/msgSeq/isFake` 逻辑完全不移动；`isFake` 仍只影响 `toString`，不是权限或存在性判断。

群管理事件创建的 `idGroup(..., isFake = false)` 也自动获得查询能力，因为它持有同一个 `QGBotImpl` 和群 OpenID。`GroupRelationImpl.group(id)` 返回的包装同样可调用 `info()`；若 ID 无效，平台错误直接暴露。

## 5. core Mock 测试要求

新增 `QGGroupManagementCoreTests.kt`，复用 `AbstractInteractionTests` 的 `MockEngine` 装配方式。至少覆盖：

1. `group.info()` 发 GET 到 `/v2/groups/group-openid/info`，快照 `name` 正确，但 `group.name` 仍为空。
2. `group.members` 在**开始收集前**没有请求；收集时以 `next_cursor` 连续 GET，且 URL 没有 `limit`。
3. `group.member(id)` 的 404 返回 `null`；11253 不被吞掉。
4. `joinRequests(autoPagination = false)` 只请求一页；`QGGroupJoinRequest.decline` 形成正确 POST body，不打印验证数据。
5. 禁言 add/update/del、移除的两种结果、黑名单 add/del 的路径和 JSON。
6. `GroupMemberAdd/Remove`、`QGGroupAuthor` 仍能构造基础成员；未提供的字段为 null，不会变成虚构的用户名或角色。

这些 Mock 测试不证明成员/黑名单接口已获得内邀资格；该界限在批次 5 的验收记录中必须保留。
