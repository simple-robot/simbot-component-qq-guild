# 批次 5：测试、兼容性与发布

## 目标

本批验证的对象是“17 个接口可被正确构造、序列化、解码，并在 core 中以预期语义暴露”。它刻意区分静态/Mock 验证与平台真实验证：后者需要白名单、内邀资格和管理员身份，不能由本地测试替代。

### 1.1 API 请求构造断言

每个测试用 `QQGuild.DefaultJson.encodeToString(api.body)` 后再 parse 为 `JsonObject`，仅比较结构和值；不要比较 JSON 文本顺序。固定检查项如下：

| 接口族 | 关键断言 |
| --- | --- |
| 群资料/状态/禁言查询 | path 恰为 `/v2/groups/{id}/...`，GET 无 body。 |
| 入群申请/策略/黑名单列表 | cursor 和 limit 只能在 URL parameters；`cursor=null`/`limit=null` 不产生空参数。 |
| 成员列表 | URL 可带 `cursor`，**不得**含 `limit`。 |
| 审批 | `approval_join_request/{member}` 的路径顺序和四个 snake_case body 字段。 |
| 禁言写入 | `members` 数组；`op=del` 且 `muteExpireAt=""` 输出空字符串，而不是省略字段。 |
| 策略 | 创建 POST、修改 PATCH、删除 DELETE、执行 POST；`group_ids` 和 `whitelist_users` 都是 string array。 |
| 移除/黑名单 | 分别使用 `batch_remove_members`、`member_blacklist`，不能混淆“移除同时拉黑”的回执字段和黑名单操作的 `fail_openids`。 |

每一个 GET/写操作至少一次；方法数必须合计 17。建议用参数化数据表减少重复，但不要把路径断言抽象到看不见具体资源的辅助函数，接口名/路径错误应在失败输出中一眼可见。

### 1.2 反序列化夹具

以 [官方资料](../reference/官方接口资料与原始示例.md) 的 JSON 为基础，存为测试内 `trimIndent()` 常量或 `commonTest/resources`。夹具必须覆盖：

1. 含 `review_qa_list` 的入群申请，验证答案原样可解码但不打印。
2. 禁言响应中的定时规则、跨天周期规则和成员禁言。
3. 以 `group_ids` 表示的策略与遮掩的 string QQ 群号。
4. 成员列表和详情、黑名单用户、两个部分成功回执。
5. 官方机器人状态示例的修正版：官方原文不是合法 JSON，测试夹具补齐 `"member"` 的闭合引号，并在测试注释写清楚该修正；不要把官方坏文本当作“服务端响应格式”。

未知键测试应给每种主要响应加一个未识别字段，验证已有 `ignoreUnknownKeys = true` 的兼容性。未知字符串值则验证能落入 `String` 原值，而不是因 enum 解析抛异常。

### 1.3 core MockEngine 场景

使用当前 `AbstractInteractionTests` 的 app/bot 创建方式。测试处理器按 `request.method` 和完整 `request.url` 路由，返回最小合法 JSON；每个测试 `finally` 取消 app 和 bot，避免协程泄漏。

必须覆盖的流程：

```text
QGGroup.info()                         GET /info -> QGGroupInfo
QGGroup.botState()                     GET /bot_state -> QGGroupBotState
collect(group.members)                 GET members?cursor= -> next_cursor -> 第二页
group.member(absent)                   平台 404 -> null；11253 -> 抛出
collect(group.joinRequests(false))     只请求第一页
request.decline(..., true)             POST 审批 + 正确 body，不自动第二个请求
group.updateMemberMutes(...)            POST 禁言 body
group.removeMembers(..., true)         POST 移除 + 分别读取部分结果
collect(group.blacklistedMembers())    GET 黑名单分页
group.addMembersToBlacklist(...)       POST 黑名单，失败 ID 原样返回
bot.joinApprovalStrategies.list()      GET 策略分页
handle.execute()                       POST execute；不 delay、不 poll
```

取消语义另测：策略/面板同样的 `IGNORE_ON_FAILURE` 分支只吞普通失败，`CancellationException` 必须继续传播。测试里不使用真实 appId、token、secret、群 OpenID 或成员 OpenID。

### 2.2 建议验证命令与判读

在干净的构建环境依次执行，命令应根据本仓库 Gradle wrapper 的实际任务列表调整，不应把失败的网络依赖下载伪称为代码失败：

```bash
./gradlew :simbot-component-qq-guild-api:allTests --no-daemon
./gradlew :simbot-component-qq-guild-core:allTests --no-daemon
./gradlew :simbot-component-qq-guild-api:compileKotlinJvm :simbot-component-qq-guild-core:compileKotlinJvm --no-daemon
./gradlew apiCheck --no-daemon
git diff --check
```

若项目的 compatibility 插件约定需要更新基线，先运行其 `apiDump` 任务，再重跑 `apiCheck`；每次都审阅 dump diff。不要在没有证据时宣称 JS/Native 已验证：`allTests`/编译任务的具体 target 覆盖必须从本机 task 输出确认。若 Gradle 因缓存、JDK 或仓库访问受阻，报告准确的阻塞命令和错误边界，仍可交付静态审阅结论。

## 3. 真实平台联调（可选、受控）

真实验证必须在平台授予资格后单独执行，不能作为默认测试。准备条件：

| 组别 | 必要条件 | 最小动作 |
| --- | --- | --- |
| 群资料/机器人状态 | 对应 11253 白名单资格、测试群 | 只 GET，记录 HTTP 状态/trace ID，不记录完整响应。 |
| 申请/审批/禁言 | 机器人为测试群管理员，专用测试申请人 | 拉取一页、对测试申请 approve/decline、对测试普通成员短时禁言后解除。 |
| 策略 | 机器人为关联测试群管理员，专用低风险白名单号码 | 创建短期策略、加/删一个白名单、调用一次 execute；只验证请求受理，不等十分钟后自动判成功。 |
| 成员/黑名单 | 平台内邀资格、可牺牲的测试成员 | 单页成员查询、详情、黑名单 add/del；移除测试成员只在明确授权后进行。 |

凭证只能由环境变量或忽略的本地配置提供，默认缺失即跳过。输出只允许接口名、HTTP status、trace ID、脱敏计数和是否成功；不输出 Authorization、secret、验证答案、拒绝原因、完整 QQ 号/OpenID。任何移除、拉黑、审批拒绝都必须限定为事先约定的测试对象，且在操作日志中记录可恢复路径。

## 4. 发布前验收表

| 分类 | 通过条件 | 不能替代它的东西 |
| --- | --- | --- |
| 契约 | 17 个 path/method/字段与资料逐项核对 | 仅能编译。 |
| 序列化 | 请求 JSON 与解码夹具测试通过 | Mock 的固定字符串不经 serializer。 |
| core 语义 | 冷分页、404 映射、无缓存、无隐式多请求均有测试 | 仅调用低层 API。 |
| 二进制/API | apiCheck、dump diff、JPMS 编译通过 | Kotlin 源码编译。 |
| 安全 | 无凭证夹具；无新增敏感日志；DEBUG 风险已写 KDoc | 不打印 token 的一次测试运行。 |
| 平台 | 有资格时完成受控最小联调；无资格时明确标“未验证” | 单元测试、HTTP 200 mock。 |
| 文档 | README/能力清单与内邀限制更新 | 代码注释。 |

全部静态与 Mock 项完成、真实平台项如实记录后，才可把本能力标为 SDK 已实现。若没有内邀/白名单条件，正确的发布说明应为“SDK 契约与 Mock 验证通过；平台资格相关联调未完成”，而不是“所有接口已在线验证”。
